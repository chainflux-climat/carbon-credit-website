# Applicability check

> The applicability check evaluates every applicability condition of the chosen methodology against the project's intake and returns one of three results for each: pass, fail, or needs review. It is rule-based, not generated, and a condition that calls for judgment is sent to a person instead of being guessed.

Updated 2026-09-29. Canonical: https://climat.today/product/applicability-check/

## What does the applicability check do?

It takes the applicability conditions of the methodology you chose and tests your project against each one. Nothing is skipped: a methodology with nine conditions produces nine results.

The check runs as soon as the intake is submitted, before any drafting. If the methodology does not fit, you find out before you have spent time on a document.

## What do the three results mean?

| Result | Meaning | What to do |
| --- | --- | --- |
| Pass | The input you gave satisfies the condition as the methodology states it. | Make sure the evidence behind the input is uploaded. The validator will ask for it. |
| Fail | The input you gave does not satisfy the condition. | Check the input. If it is correct, the project does not fit this methodology as described. |
| Needs review | The condition calls for judgment, or its input has not been supplied. | A person on your team has to make the determination and record why. |

## Which conditions are sent to a person?

Some conditions are thresholds: a density, a date, a capacity. Those can be computed. Others ask whether an arrangement meets a description, and turn on facts a form cannot capture. Climat marks those as needs review and does not attempt an answer.

For background on how validators read these conditions, see the guide to [applicability conditions](https://climat.today/guides/applicability-conditions/).

## Which methodologies does it cover?

The check covers the methodologies Climat supports today: [Verra VM0047](https://climat.today/methodologies/vm0047/) version 1.1, census-based approach, and [Verra VMR0017](https://climat.today/methodologies/vmr0017/) version 1.0. Conditions are set up from the published methodology text.

## Frequently asked questions

### Is the applicability check done by a language model?

No. The check is rule-based. Each condition is written down from the published methodology with the input it depends on and the test it applies, and the result is computed from your intake. The same inputs always give the same result.

### What happens if an input has not been provided yet?

The condition is reported as needs review. A condition is never reported as passed because its input is missing.

### What should I do if a condition fails?

A failed condition means the project, as described, does not fit the methodology. Check the input first. If it is right, the options are a different methodology, a change to the project, or a deviation under the registry's own rules, which a validator has to accept.
