# The Verra VCS project description: every section and what it must establish

> The Verra VCS project description is written on VCS Project Description Template v5.0A or v5.0B, both issued 9 June 2026. Each has five numbered sections (project details, safeguards and stakeholder engagement, application of methodology, quantification, monitoring) and two standing appendices. A project start date before 1 January 2027 means v5.0A; on or after that date, v5.0B.

Updated 2026-09-30. Canonical: https://climat.today/registries/verra-vcs/

- **Current edition:** VCS Version 5, released 16 December 2025
- **Templates:** VCS Project Description Template v5.0A and v5.0B, issued 9 June 2026, effective 1 January 2027
- **Which template:** v5.0A for a project start date before 1 January 2027; v5.0B on or after that date
- **Structure:** 5 numbered sections and 2 standing appendices; 36 numbered subsections in v5.0A, 37 in v5.0B
- **Crediting period (VCS Standard v5.0, section 3.8.4):** 5 years for energy and industry, geological carbon storage, livestock systems, and agricultural land management without soil organic carbon stock change; 20 to 100 years for the other AFOLU categories
- **Public comment period:** 30 days, starting when the project is listed as under validation
- **Fees (Verra Program Fee Schedule v1.2):** USD 1,500 pipeline listing, USD 3,750 registration review, USD 0.23 per tCO2e issuance levy

## Which version of the VCS Program is current, and which documents govern a project?

VCS Version 5 is the current edition. Verra released it on 16 December 2025, and section 1.1 of the [VCS Program Guide v5.0](https://verra.org/documents/vcs-program-guide-v5-0/) states that it replaces Version 4 as the applicable version. Each update has its own effective date, listed in the [overview of updates and effective dates](https://verra.org/documents/vcs-version-5-overview-of-vcs-program-updates-and-effective-dates/). Verra's [rules page](https://verra.org/programs/verified-carbon-standard/vcs-program-details/) lists the VCS Standard v4.7 as active until 1 January 2027.

| Document | What it governs |
| --- | --- |
| VCS Program Guide v5.0 | The overarching document: program scope, roles, the registry, and how effective dates work |
| [VCS Standard v5.0](https://verra.org/documents/vcs-standard-v5-0/) | The requirements for developing a project and for validation and verification |
| [Registration and Issuance Process v5.0](https://verra.org/documents/registration-and-issuance-process-v5-0/) (RIP) | The procedures for pipeline listing, registration, Verra's review, and issuance of Verified Carbon Units (VCUs) |
| [VCS Methodology Requirements v5.0](https://verra.org/documents/vcs-methodology-requirements-v5-0/) | The requirements for methodologies, modules and tools. A project meets them through the methodology it applies |

All four are dated 16 December 2025. The [Corrections and Clarifications of 9 June 2026](https://verra.org/documents/corrections-and-clarifications-cc-to-the-vcs-program-rules-published-9-june-2026/) amend the Standard and the RIP, and the Program Guide requires proponents and validation/verification bodies (VVBs) to apply them.

## Which project description template applies, v5.0A or v5.0B?

The project start date decides. Each template states the rule on its first page. Verra issued both on 9 June 2026, with an effective date of 1 January 2027.

- **[Template v5.0A](https://verra.org/documents/vcs-project-description-template-v5-0a/).** A project with a start date before 1 January 2027 that submits a pipeline listing request, a registration request, or, before 1 January 2030, a crediting period renewal request or a verification approval request that includes a baseline reassessment.

- **[Template v5.0B](https://verra.org/documents/vcs-project-description-template-v5-0b/).** A project with a start date on or after 1 January 2027, for any request that requires a project description. Also an earlier project that submits a renewal request, or a verification approval request with a baseline reassessment, on or after 1 January 2030.

The templates differ in the rules they report against. v5.0A applies sections 3.7, 3.18 and 3.19 of the [VCS Standard v4.7](https://verra.org/documents/vcs-standard-v4-7/): ownership, stakeholder engagement and safeguards. v5.0B applies sections 3.6, 3.17 and 3.18 of the VCS Standard v5.0. Neither is for a project that must use the digital template in the Verra Project Hub. For what the document is and who reads it, see [what a project design document is](https://climat.today/guides/what-is-a-pdd/).

## What does each section of the project description have to establish?

The table follows Template v5.0A, in the template's own order and with Verra's section names. The template's instructions are mandatory. A section that does not apply is explained and justified, not deleted.

| Section (v5.0A) | What it has to establish |
| --- | --- |
| 1 Project Details | What the project is, who runs it, and that it is eligible |
| 1.1 Summary Description of the Project | In one page: technologies or measures, location, how reductions or removals arise, the prior scenario, estimated annual and total volumes |
| 1.2 Audit History | Every audit to date and the forthcoming one |
| 1.3 Sectoral Scope and Project Classification | Sectoral scope, project category and project activity type |
| 1.4 Project Eligibility | Listing and registration deadlines met; eligibility of agriculture, forestry and other land use (AFOLU) projects; status under any other GHG program; not a fragment of a larger project under a capacity limit |
| 1.5 Project Proponent | Organization and contact for each proponent |
| 1.6 Other Entities Involved in the Project | Every other entity and its part in implementation, management and monitoring |
| 1.7 Ownership | How project ownership is established, with the evidence |
| 1.8 Project Start Date and Initial Crediting Period Start Date | Both dates, and the significant action that fixes the start date |
| 1.9 Project Crediting Period | Length, start and end dates, period number, maximum total duration |
| 1.10 Project Scale | Project or large project (over 300,000 tCO2e a year), with an estimate for each calendar year |
| 1.11 Project Design | Single instance, multiple instances, grouped project or expanding geological carbon storage (GCS) project; for a grouped project, the eligibility areas and criteria for adding instances |
| 1.12 Conditions Prior to Project Initiation | Existing facilities and equipment, or for AFOLU the ecosystem type, land use and environmental conditions |
| 1.13 Description of the Project Activity | Technologies or measures, how they achieve the reductions or removals, and the implementation schedule |
| 1.14 Project Location | Country down to municipality, maps, and a geolocation file attached separately |
| 1.15 Compliance with Laws and Other Regulatory Frameworks | Each relevant law and how the project complies; screening for politically exposed and sanctioned persons |
| 1.16 Double Counting and Participation with Other GHG Programs | No double issuance; any registration with, or rejection by, another GHG program |
| 1.17 Double Claiming, Other Forms of Credit, and Scope 3 Emissions | No double claiming under an emissions trading program, a binding limit or another environmental credit; supply chain emissions |
| 1.18 Sustainable Development Contributions | Each contribution, with its Sustainable Development Goal target, indicator, baseline and expected result |
| 1.19 Additional Information | Leakage management, whether information is withheld as sensitive, and anything else bearing on eligibility or quantification |
| 2 Safeguards and Stakeholder Engagement | That people and ecosystems were consulted and protected, under the VCS Standard v4.7 |
| 2.1 Stakeholder Engagement and Consultation | Stakeholder identification, consultation and ongoing communication, free, prior and informed consent (FPIC), the grievance redress procedure, and public comments with the action taken |
| 2.2 Risks to Stakeholders and the Environment | Management experience, the risks identified, and mitigation measures |
| 2.3 Respect for Human Rights and Equity | Risks and mitigation for labor, human rights, Indigenous Peoples and cultural heritage, and property rights; benefit sharing |
| 2.4 Ecosystem Health | Risks to biodiversity, soil and water; rare, threatened and endangered species; species introduced; ecosystem conversion |
| 3 Application of Methodology | That the methodology fits, and what follows from it |
| 3.1 Methodology Details | Each methodology, module and tool applied, with ID and version |
| 3.2 Applicability and Eligibility of Methodology | That each is listed by Verra and active when the request is submitted; every [applicability condition](https://climat.today/guides/applicability-conditions/) justified separately |
| 3.3 Project Boundary | Carbon pools, and GHG sources and sinks for baseline, project and leakage; anything deemed de minimis |
| 3.4 Baseline Scenario | The method used, applied step by step, with the outcome of each step; baseline reassessment when due |
| 3.5 Additionality | Regulatory surplus, then the [additionality](https://climat.today/guides/additionality/) method, with enough data to reproduce the analysis |
| 3.6 Methodology Deviations | Each deviation, its justification, and that it concerns only monitoring or measurement |
| 4 Quantification of Estimated Reductions and Removals | The ex-ante numbers, reproducible by a reader |
| 4.1 Baseline Emissions, 4.2 Project Emissions, 4.3 Leakage Emissions | For each: procedures, numbered equations, justified choices, and enough information to reproduce the calculation |
| 4.4 Other Relevant Quantification | Non-permanence risk rating, buffer pool allocation, and the long-term average for afforestation, reforestation and revegetation (ARR) and improved forest management (IFM) projects with harvesting |
| 4.5 Estimated GHG Emission Reductions and Carbon Dioxide Removals | Net estimates for each vintage period, with reductions and removals separated where the methodology allows |
| 5 Monitoring | How the data will be collected and controlled |
| 5.1 Data and Parameters | A cross-reference to Appendix 2 |
| 5.2 Monitoring Plan | Data collection and management, calibration, personnel, internal auditing and QA/QC, non-conformances, sampling |
| Appendix 1: Sensitive Information | What is withheld from the public version, and why it qualifies |
| Appendix 2: Data and Parameters | Each parameter fixed at validation (A2.1) and each parameter monitored (A2.2) |

## How does a project get from listing to registration?

The [Registration and Issuance Process, v5.0](https://verra.org/documents/registration-and-issuance-process-v5-0/), splits the path into a pipeline listing stage and a registration stage, and the project description is written twice over.

1. **Listing as under development.** A partial project description is enough, and indicative figures are acceptable. The file is submitted as `VCS_PD_DRAFT`. Verra charges USD 1,500 for each pipeline listing request.

2. **Listing as under validation.** The proponent submits the full documentation set, including a completed project description, to move the status on (Section 3.1.16). A second listing representation is not required.

3. **The 30-day public comment period.** It starts on the date the status becomes *under validation*, and the project stays on the pipeline as under validation for the whole 30 days (Section 3.1.17). Comments go through the Verra Project Hub; respondents give a name, organization, country and email address. Verra shares every comment with the proponent at the end, posts a public summary, and the proponent addresses them as the VCS Standard requires.

4. **Validation.** Once the comment period completes, the validation and verification body may conclude validation (Section 3.1.20). Validation has to be complete before registration is requested (Section 4.1.1).

5. **Registration review.** The registration request costs USD 3,750. Verification approval follows on its own track, and a proponent must submit a verification approval request within five years of the approval date of the registration request or of the most recent verification approval request (Section 4.1.2).

A project that stops responding loses its place: Verra may reject a project where it receives no reactivation request within 12 months of the status changing to inactive, and from 15 April 2026 it began inactivating pipeline projects that do not respond to findings within 90 days at the listing stage.

## Which crediting period applies?

Table 8 in section 3.8.4 of the [VCS Standard, v5.0](https://verra.org/documents/vcs-standard-v5-0/), sets the length by project type, and the change lands with registration requests submitted on or after 1 January 2027.

| Project type | Crediting period | Times renewable | Maximum total |
| --- | --- | --- | --- |
| ALM with SOC stock change, ARR, IFM, REDD, WRC, ACoGS | 20–100 years | 4 | 100 years |
| Geological carbon storage (GCS) | 5 years | 8 | 45 years |
| Energy and industry (E&I), ALM without SOC stock change, livestock systems | 5 years | 2 | 15 years |

Verra's stated reason for the five-year periods is to make projects update to an active methodology and reassess their baselines more often. For the long AFOLU periods, baseline reassessment intervals were shortened to five years, or to whatever the applied methodology sets. For geological carbon storage the five-year renewal and the 45-year maximum took effect immediately for projects that initiated listing on or after 16 December 2025, and at the first renewal request for those listed before it. A renewal request has to reach Verra within two years of the end of the previous crediting period, or within two years of Verra approving a new methodology where the project is switching to one (Section 3.8.9).

## What does it cost?

From the [Verra Program Fee Schedule, v1.2](https://verra.org/documents/verra-program-fee-schedule-v1-2/). These are registry fees only: they exclude the validation and verification body's own fees, which are negotiated with the VVB and are usually the larger number.

| Fee | Rate |
| --- | --- |
| Registry account opening | USD 750 per account |
| Annual account maintenance | USD 750 per account |
| Pipeline listing | USD 1,500 per request |
| Registration review | USD 3,750 per request |
| Verification review | USD 5,000 per request — USD 2,500 review fee plus a USD 2,500 prepayment credited against future issuances |
| VCU issuance levy | USD 0.23 per claimed tCO 2 e of reductions or removals |

Two fees are worth planning for separately. The prepayment means a project pays no issuance fee on its first USD 2,500-worth of VCUs, and it is not charged again if a returned verification request is resubmitted. And projects using module VMD0055 for avoided unplanned deforestation pay a project activity data allocation fee of USD 10,000 per request plus USD 0.25 per hectare in the submitted KML, capped at USD 150,000 per project.

## How Climat handles this

Climat drafts against a seeded description of the registry's document rather than against the PDF template. For VCS that seed is a ten-section list — project description, project boundary, application of the methodology, demonstration of additionality, baseline scenario, quantification, monitoring, data and quality management, environmental and social safeguards, and crediting period — in that order, because the drafting order is the registry's, not ours.

That list is a working decomposition, not the template. Template v5.0A and v5.0B put the same material under five numbered sections and two appendices, and they are the authority: a person maps Climat's sections onto the template's numbered subsections, and fills the title page, the sensitive-information appendix and the data-and-parameters appendix, before anything is submitted. Climat drafts, cites and flags; it does not produce a file for upload to the Verra Project Hub, and it is neither a registry nor a validation and verification body. Our [guide to project design documents](https://climat.today/guides/what-is-a-pdd/) covers what each section has to establish, and [validation and verification](https://climat.today/guides/validation-and-verification/) covers what the VVB does with it.

## Frequently asked questions

### How many sections does the VCS project description template have?

Five numbered sections: Project Details, Safeguards and Stakeholder Engagement, Application of Methodology, Quantification of Estimated Reductions and Removals, and Monitoring. Two standing appendices follow, for sensitive information and for data and parameters. Template v5.0A has 36 numbered subsections and v5.0B has 37, because v5.0B renames the second section Stakeholder Engagement and Safeguards and gives it five subsections instead of four.

### Does a project that started before 2027 ever move to template v5.0B?

Yes. Template v5.0B applies to a project with a start date before 1 January 2027 when it submits a crediting period renewal request, or a verification approval request that includes a baseline reassessment, on or after 1 January 2030. Until then the project reports on v5.0A.

### Which sections must be drafted to list a project as under development?

The Corrections and Clarifications of 9 June 2026 list them for requests submitted on or after 1 January 2027: the title page, sections 1.1 to 1.5, 1.8 to 1.13 and 1.15 to 1.17, the grievance redress section (2.1.4 in v5.0A, 2.4 in v5.0B), and sections 3.1 and 3.2. Indicative information is sufficient at that stage. Listing as under validation requires a project description with all sections completed.

### Does a renewable energy project need a non-permanence risk report?

No. Under section 3.2.8 of the VCS Standard v5.0, non-permanence risk analysis applies only to reductions and removals generated through carbon sinks, and activities that reduce N2O, CH4 or fossil fuel-derived CO2 are not subject to it. The template still keeps the heading: the proponent explains that the section is not applicable.

### How long is the crediting period of a renewable energy project under VCS Version 5?

Five years, renewable twice, for a maximum of 15 years, under Table 8 in section 3.8.4 of the VCS Standard v5.0. Verra's overview of effective dates applies the change to registration requests submitted on or after 1 January 2027. The VCS Standard v4.7 allowed seven years, twice renewable, or ten years fixed.

### In what format is the project description submitted?

As a non-editable PDF, in English. The template sets the file name from the document type, the project ID, the completion date and the version, for example VCS_PD_DRAFT for a listing request as under development and VCS_PD for a registration request. Where the applied methodology has been digitalized, the VCS Standard v5.0 requires the digital template in the Verra Project Hub instead.
